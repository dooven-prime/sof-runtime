# Prefix Integrity Attribution: Local Readout

Status: **PASS_LOCAL_ATTRIBUTION_CONTROLS**. Planned disposition:
**STOP_FIXED_CAPTURE_ACCELERATION**. All verification remains enabled.

## Scope and Controls

Use the unchanged 64-slot capture and a fixed **62-slot committed prefix**.
Four original states were generated by actual v1 execution and process kill
at checkpoint publication. Each was copied once. Two pairs measured the
original before copying; two copied first and measured the copy first.
Two further explicit read-warm rounds alternated original/copy order.
The complete predeclared schedule has **24 measured probe processes**.

Every probe independently validated the prior checkpoint anchor, identity,
cursor, chain and inventory; prefix raw bytes; segment hashes, lengths and
record counts; streamed prefix aggregate; and post-consumption source/state
stability. No block was decoded and no new slot was committed. All 24 scratch
aggregates and eight unchanged states matched the full Python prefix.

Per probe, the key logical byte counts were:

| Work | Bytes |
|---|---:|
| Prefix raw responses hashed | 2,577,584 |
| Prefix segments validated | 1,940,724 |
| Prefix aggregate read / written | 1,940,724 / 1,940,724 |
| Checkpoint/anchor phase reads, including fixed v1 executable | 548,411 |
| Post-consumption integrity reads | 2,722,682 |

These are application read/write counts, not physical disk bytes. Metadata
admission is separately timed but has no application-level read count; the
unmodified parser's internal I/O is not reinterpreted as zero.

Eight focused test methods passed in both ordinary and optimized Python.
They cover corruption, cursor/anchor/identity failures, writer exclusion,
post-consumption input checking, output confinement, unchanged state, exact
byte accounting and the frozen stop classifier. Changing mtime alone does not
reject valid content; changing content while restoring mtime is rejected,
including after explicit pre-reading. The two inherited Rust parser tests
also passed; they are not new adequacy or recovery proofs.

## Four-Phase Attribution

Median wall times in milliseconds. Initial groups have four observations;
read-warmed groups have eight. Phase medians are not additive decompositions
of one invocation.

| State / condition | Raw input hash | Segment validation | Checkpoint / anchor | Aggregate streaming |
|---|---:|---:|---:|---:|
| Original, initial | 14.091 | 8.320 | 4.624 | 9.639 |
| Copied, initial | 13.324 | 1,014.579 | 21.281 | 12.663 |
| Original, read-warmed | 13.623 | 7.252 | 4.099 | 8.940 |
| Copied, read-warmed | 13.894 | 7.515 | 3.880 | 9.544 |

The observed penalty is concentrated in the **first copied-segment
validation**, not the raw-input SHA computation or aggregate construction.
For all four copied initial runs, raw-input plus segment validation wall time
was 0.988--1.075 s, versus 0.015625--0.031250 s of process CPU. Their warmed
counterparts had pair medians of 0.0193--0.0266 s wall. The initial/warmed ratios
were **38.5--55.8**; initial wall/CPU ratios were **31.6--68.8**.

This meets the predeclared non-CPU/file-state-sensitive classification in
**4/4 pairs**, exceeding its 3-pair threshold. It does not say that warmed
validation is non-CPU work: short warmed phases are already cheap and have
quantized CPU readings. It explains the large **initial-copy penalty** seen
in the earlier recovery curves, within this local diagnostic scope.

Copied segments had the same lengths and preserved mtimes as originals, but
distinct file IDs and new creation times. File attributes were retained in
the record. This supports reporting a materialization/first-access-sensitive
effect, not using metadata as an integrity substitute. No specific disk,
filesystem, cache, antivirus or scheduler mechanism was isolated.

Metadata admission remained about 32--34 ms and post-consumption integrity
about 28--30 ms across conditions. The largest observed OS-reported peak
working set was 5,615,616 bytes. This is a local observation, not a worst-case
memory bound. Individual CPU, wall, process-I/O and file-state records remain
available in the full receipt.

## Measurement Limits

No forced cold cache, isolated host or operational-load guarantee. A separate
Rust debug test build ran during this local experiment; it was not part of
the measured child and is a background-activity limitation. All four pairs
show the copied-only initial pattern, but the experiment does not identify
which external service accounts for off-CPU time. No further timed run was
added to obtain a preferred result.

The probe separates and groups checks that the original v1 interleaves. Its
aggregate covers 62 committed slots, not the two unprocessed suffix slots.
It is an attribution probe, not another full replay performance comparison.
File copying, explicit pre-reading and metadata observation occur outside
probe process timers and are recorded; their costs have not disappeared.
Pre-reading moves work outside the measured probe and is **not** proposed as
an end-to-end optimization or a validation credential.

There is no demonstrated semantic-preserving computation optimization to
implement here: the large penalty is not explained by process CPU, while
avoiding reads or accepting a weaker identity would change the guarantee.
Accordingly **stop chasing acceleration on this fixed capture**. Preserve
the frozen replay and all checks. The next independent task can specify real
input advancement, source correction and checkpoint invalidation; none is
implemented or implied by this attribution result.
